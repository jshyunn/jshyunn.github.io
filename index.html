Strengths

보안은 기술 적용과 함께 지속적인 검증으로 완성된다고 생각합니다.
환경에 맞는 보안 체계를 설계하고, 남은 위협을 데이터로 탐지하며, 탐지 결과의 분석과 판단까지 자동화해 지속적으로 보완하겠습니다.

  1. 01보안 아키텍처 설계

    보안 요구사항을 분석하고 환경에 맞는 보안 체계를 설계할 수 있습니다. 금융보안원과 함께 제로트러스트 가이드를 개발하고 직접 테스트베드를 구축하며 환경에 따라 필요한 기술과 적용 방식이 달라져야 함을 확인했습니다. 또한 기술을 적용하는 데서 그치지 않고 채워지지 않는 부분은 찾아 개선했습니다. 필요한 보안 기술을 선택하고 남은 공백은 보완해 실제 환경에서도 안전한 보안 체계를 만들겠습니다.

  2. 02데이터 기반 위협 탐지

    보안 데이터를 분석해 환경에 맞는 위협 탐지 기술을 설계할 수 있습니다. 도로교통과 제로트러스트 환경의 데이터를 분석하며 모델의 복잡도보다 데이터와 운영 환경의 특성을 반영하는 것이 중요함을 확인했습니다. 트래픽의 반복성과 사용자별 접근 범위처럼 환경에서 나타나는 특징을 탐지 기준에 반영하고 오탐과 처리 효율을 개선해왔습니다. 데이터의 특성에 맞는 탐지 기준을 설계해 실질적인 위협을 찾아내겠습니다.

  3. 03LLM 기반 보안 업무 자동화

    LLM은 서로 다른 형태의 정보에서도 문맥을 이해하고 필요한 정보를 추출할 수 있습니다. 금융 AI 서비스 공모전에서 정형과 비정형 정보를 함께 다루며 이 가능성을 확인했습니다. 보안 관제에서도 네트워크·시스템·사용자 행위처럼 서로 다른 로그와 이벤트가 동시에 발생합니다. LLM을 활용하면 개별 정보만 보던 방식에서 관련 이벤트를 묶어 분석하는 방식으로 넘어갈 수 있다고 생각합니다.

제로트러스트 환경 사용자 이상 행위 탐지 연구

국민대학교 일반대학원 · 석사학위논문

2026.08.19

논문 보기 ↗
개요

기존 네트워크 침입 탐지 연구는 외부 공격 탐지에 집중되어 있으며, 제로트러스트 환경에서 인증 이후 사용자 행위를 지속적으로 검증하는 연구는 상대적으로 부족합니다.

방법

사용자별 접근 이력으로 평소 사용 범위를 만들고 세션의 접근이 그 범위를 얼마나 벗어나는지 점수로 판별합니다. 점수가 임계값을 넘으면 이상으로 봅니다.

비교 대상 · OC-SVM · Isolation Forest · AutoEncoder · SBERT · LSTM 등

결과
F1-Score 0.98인증 이후 사용자 이상 행위 탐지
Precision 1.00정상 사용자를 공격으로 분류한 사례 없음
AP 0.932비교 기법 7종 중 최고
문제 해결

  1. 문제 1

    연구에 활용할 데이터셋이 없었습니다.

    포기하기보다 직접 필요한 환경부터 구축했습니다. AWS에 기업 업무 환경을 모사한 테스트베드를 구축하고 최소 권한 접근통제와 네트워크 세분화를 적용했습니다. 이후 부서와 직급에 따른 정상 업무 행위와 공격 5종을 수행해 접근 로그를 수집했습니다.

  2. 문제 2

    같은 기능이라도 URI에 숫자·해시 같은 값이 섞여 있어 동일한 행위가 매번 다른 접근으로 취급됐습니다.

    URI를 경로 단위로 쪼개 Trie에 쌓고 값이 매번 달라지는 구간을 하나로 일반화했습니다. 같은 기능이 하나의 템플릿으로 묶여 기준선이 흔들리지 않게 되었습니다.

  3. 문제 3

    사용자별 접근 이력만으로 기준선을 세우니 다수가 정상적으로 쓰는 URL임에도 이상으로 잡혔습니다.

    기준선을 개인에만 두지 않고 조직 전체로 넓혔습니다. 개인에게는 처음이더라도 다수가 공통으로 접근하는 URI는 공격일 가능성이 낮다고 판단해 허용 목록을 추가했습니다. 정밀도가 0.611에서 0.757로 올라 오탐이 37.5% 줄었습니다.

  4. 문제 4

    정상 업무 중 평소와 다른 접근까지 공격으로 잡혀 오탐이 남았습니다.

    요청만으로는 정상 여부를 가릴 수 없다고 보고 서버의 응답을 근거로 삼았습니다. HTTP 상태 코드로 되짚어 실제로 정상 처리된 접근은 재분류했습니다. 정밀도가 1.000이 되어 남은 오탐이 사라졌습니다.

Detecting Unknown Cyberattacks on Traffic Management Center in C-ITS

IEEE Communications Magazine (JCR Top 10% SCIE)

2026.01.16

논문 보기 ↗ 코드 보기 ↗
개요

C-ITS 교통관리센터는 차량·노변장비·인프라의 데이터를 모아 실시간 교통 서비스를 운영합니다. 통신이 암호화되어 있어 기존 DPI 탐지 방식은 공격을 식별할 수 없고, 기존 연구는 차량 보안에 집중되어 있습니다.

방법

패킷 수·바이트량·지속시간 같은 메타데이터를 로그 이산화해 시그니처로 만들고, 정상 시그니처를 모은 화이트리스트에 없는 흐름을 이상으로 판별합니다.

비교 대상 · Isolation Forest · AutoEncoder · SVM

결과
F1-Score 0.99울산 TMC 실제 운영 데이터 · 비교 3종 중 최고
F1-Score 0.88CIC-IDS2017 공개 벤치마크 · 비교 3종 중 최고
157만 건/초처리량도 두 데이터셋 모두 최고
문제 해결

  1. 문제 1

    정상 트래픽의 양은 방대했지만 대부분이 비슷한 양상을 보였습니다.

    메타데이터 특징을 로그 이산화해 반복되는 흐름을 하나로 묶었습니다. 정상 플로우 22,362개가 대표 패턴 484개로 줄었습니다.

  2. 문제 2

    패킷 양에 비해 추출된 플로우 수가 지나치게 적었습니다.

    기존 변환기가 TCP 종료를 처리하지 못해 여러 플로우가 하나로 합쳐지고 있었습니다. 대신 CICFlowMeter를 활용해 데이터를 9배 확보했습니다.

  3. 문제 3

    대표 패턴으로 비교 대상을 줄이고도 비교 기법에 비해 처리 효율이 떨어졌습니다.

    각 시그니처를 해싱해 64비트 키로 바꿔 집합 조회만으로 판별하도록 했습니다. 비교 기법 대비 처리량은 최대 5.6배 높고 메모리는 최대 67% 적었습니다.

  4. 문제 4

    피처를 늘리자 시그니처가 표현하는 범위가 잘게 나뉘며 개수만 늘어나 오탐이 많아졌습니다.

    로그 밑을 고정값이 아니라 하이퍼파라미터로 두어 환경에 맞춰 조정되도록 했습니다. 다양한 환경에서도 안정적인 성능을 확보했습니다.
